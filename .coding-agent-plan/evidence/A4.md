# A4 — Verification oracle and result truth

Status: done

## Implemented contract

- Agent Core checks now have an exact, persisted implementation identity and a discriminated execution contract: deterministic checks run inside the driver; executable checks prepare a durable effect with exact authorization, recovery identity, one-shot start authority, settlement, and reconciliation. The old hidden `runCommand` callback was deleted.
- Verification is an authoritative operation phase bound to the exact provider settlement, turn identity, admitted check list, preparation fingerprint, effect state, and settled result. A restarted process reconstructs the exact turn and reconciles a started check without calling the provider or verifier twice.
- `AgentSession` supplies the accepted submission and run identity to its runtime factory before any run effect. Coding Agent uses that boundary to capture and privately persist one immutable pre-edit workspace baseline per run; a resumed run must load the same baseline and cannot silently recapture the edited workspace.
- Project command checks require an explicit `targeted` or `full` coverage declaration. Their implementation identity binds command, requirement, coverage, timeout, and output bounds. Project configuration remains a proposal admitted only in a trusted workspace and cannot grant command authority.
- Before execution, Coding Agent captures the exact candidate and rejects incomplete capture or any changed test, package script/manifest, compiler/build configuration, CI workflow, dependency lock, or other recognized verifier definition. Legitimate verifier changes remain visible but cannot independently certify themselves.
- A check runs through the durable no-network Sandbox authority against a fsynced private materialization of the exact candidate outside the authoritative workspace. Verifier writes can affect only that copy. Added/generated outputs are recorded; a verifier that changes its own definition becomes inconclusive.
- Results distinguish targeted/full coverage, passed checks, nonzero exits with no pre-edit execution result, unavailable execution, partial capture, changed verifier definitions, and isolated-workspace changes. A nonzero exit is not mislabeled as a candidate regression when no durable baseline execution was observed.
- Baselines and candidate copies are removed after a terminal run. Suspended or uncertain effects retain their private state for exact reconciliation.

## Deliberate limits

- Coding Agent does not execute a pre-edit verifier command outside a durable operation merely to obtain a baseline result. Until a concrete early slice proves a separate baseline execution phase is worth its effect and cost, results record `baselineOutcome: not_observed` and never infer regression causality.
- Ecosystem dependency closure is not guessed. If aliases, oversized dependencies, or other unadmitted content prevent an exact snapshot, verification is inconclusive. V0 must prove a useful self-contained check and decide whether a narrowly specified dependency-input contract is needed before broadening the surface.
- Exact rollback remains deferred. Verifiers cannot mutate the authoritative workspace; private candidate-copy retention after abnormal process death is audited again in A7/F0.
