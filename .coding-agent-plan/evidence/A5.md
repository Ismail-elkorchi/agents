# A5 — Change accounting and review data

Status: done

## Implemented contract

- Agents `22e1c4fd3480da7e1188cd75744cb86a36930f5b` replaces the verification-only baseline with one immutable per-run workspace baseline. It retains the exact bounded file snapshot plus a sanitized Git observation outside the workspace. Git is observed on both sides of snapshot capture; semantic drift rejects admission, while differing sandbox receipt IDs do not create false drift.
- Snapshot entries distinguish validated UTF-8 text from binary content and retain kind, mode, size, and SHA-256 when the configured bounds permit it. Symlinks, special files, unreadable paths, concurrent changes, excessive depth/count/size, and total-byte exhaustion lower coverage rather than disappearing.
- Each ended run reduces the authoritative `apply_patch` start/end ledger pairs through the exported tool output schema. The resulting durable report binds every retained mutation receipt to its event ID, ledger sequence, call attempt, tool fingerprint, and patch SHA-256. Exact file operations remain recoverable from that ledger event; the report does not duplicate unbounded patch documents.
- Change attribution replays committed structured-mutation before/after hashes from the immutable baseline and compares the predicted final file state with a new exact snapshot. Hash-chain mismatch, destination collision, unknown/rolled-back outcomes, journal residue, unsettled mutation attempts, and final-state mismatch remain explicit conflicts or partial coverage. Sandbox commands and unmatched changes are classified as external or concurrent and are never labelled undoable.
- Final facts are machine-derived: changed paths, structured-mutation paths, external/concurrent paths, and verification status cannot be supplied or overridden by model prose. The CLI labels the model response as candidate narrative through its placement and prints the authoritative change/check facts separately.
- The original Git dirty/untracked observation is preserved without assuming a clean repository. Every changed path records whether it existed at run start and whether Git reported it changed then; absence of Git is `not_applicable`, not a fabricated clean state.
- Reports are bounded to 200 changed-path records and 200 mutation references, expose total/omitted counts, and must fit the private-state 4 MiB boundary. They are checksummed indirectly through private atomic publication and strictly decoded on read. Exact verification materializations and the large run baseline are deleted only after the report commits; failed report construction retains its source evidence for retry.
- Exact rollback remains deferred by C4. No compatibility reader, alias, model-derived fallback, ambient Git mutation, or command undo claim was added.

## Deliberate limits carried into V0

- Complete workspace snapshots currently walk the admitted root and may become partial at 20,000 entries, 64 MiB per file, or 512 MiB total. V0 must measure this on its real repository and decide whether a narrower, explicit candidate/dependency scope is required. It may not hide cost or missing coverage with ignored directories.
- Git status is provenance for the initial dirty/untracked label, not change truth. Exact content attribution comes from root snapshots and structured mutation receipts.
- The first release does not semantically parse free-form model prose for claims. It rejects model authority instead: only the report and terminal check records populate structured final facts. A future structured claim contract would be a new explicit domain boundary, not prose heuristics.
