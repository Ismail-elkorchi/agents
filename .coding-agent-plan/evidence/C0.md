Status: done

## Implemented contract

- Agent Core `50b0d1caf40ca7da11b8cfbc9ff598f435f3cdc5` replaced ambient workspace path services with an adopted, closable `WorkspaceFileRoot` and an independently adopted `TextPatchJournal`.
- Agent Core `2e8d731b85c502cee56467d3a07975c35793afb0` lets the application reserve private root entries without embedding Coding Agent names or policy in Agent Core.
- Agent Core `0e35d0b8eb7bc029121667e890c2c7103ac74ce3` made the interprocess journal-lock state machine tolerate a concurrently released lock and passed the lock test repeatedly.
- All generic discovery, file reads, image reads, searches, and structured mutations consume the adopted capability. `.git`, `.agent-core`, `.agent-core-*`, and application-supplied private root entries are denied at canonicalization.
- Linux authority is established by walking the absolute root through held directory descriptors, opening every caller-controlled component with `O_NOFOLLOW`, rejecting mount changes, non-regular files, and multiply linked files, and retaining the physical root when its display path is replaced.
- Structured mutations bind an exact file identity and SHA-256 before state, stage within the adopted root, journal exact ownership, synchronize files/directories, and retain uncertain residue rather than deleting state the journal cannot prove it owns.
- `LocalToolHost` consumes an application-supplied artifact repository and patch journal. Artifact persistence remains a separate authority rather than being manufactured from the workspace capability.
- Coding Agent and Writing Agent now construct those authorities explicitly and reserve repository-local private state until A1 moves it outside the workspace.

## Platform decision

- The current package-owned confinement primitive is supported only on Linux because Node exposes the held directory through `/proc/self/fd`. Linux is the only platform on which C0 file actions claim hostile path-swap containment.
- Windows and macOS fail during root adoption. Their test lane proves unavailability rather than silently falling back to lexical or `realpath` checks. Native handle-relative implementations are not required by the first resilient release unless those platforms need enabled host file tools.
- Command execution is not claimed by C0. `commandDirectory()` remains a temporary display-path bridge and is replaced by C2/S0; sandbox confinement is independent of host file confinement.

## Adversarial coverage

- lexical `..`, absolute, UNC/device, backslash, null-byte, reserved/private entries;
- symlink and magic-link chains, hard links, special files, mount crossings;
- root path replacement after adoption;
- concurrent parent replacement during reads and structured writes;
- identity/hash conflicts during create, replace, and delete;
- corrupted/checksum-invalid journals, unproven created directories, replaced journal display paths, expired operation authority, hard process loss, and separate-process locking;
- capability use after release.

## Residual limits

- No portable confinement guarantee is claimed. Unsupported platforms make the capability unavailable.
- C0 does not authorize content for provider egress and does not make repository configuration trustworthy; SEC0 owns those decisions.
- C0 does not make repository-local private state acceptable. A1 moves it to the user-state authority.
