# C3 — Deterministic candidate disposition

Status: done

## Implemented contract

- Agent Core now admits one versioned disposition policy whose exact canonical input contains only the persisted candidate, ordered check results, provider/candidate/check event receipts, durable budget snapshot, owned-control generation, and captured policy identity. The immutable operation configuration binds the evaluator implementation ID and policy hash.
- Deterministic evaluators are synchronous pure functions. Their canonical input digest is persisted before evaluation; the exact parsed decision and output digest are appended idempotently before the operation advances. Effect policies cannot return a decision directly: they must return a branded prepared effect and use the existing generation-fenced ticket, start, settlement-permit, reconciliation, exposure, and release contracts.
- The strict current operation schema has explicit `ready`, `effect_ready`, `effect_pending`, `outcome_unknown`, and `decided` disposition stages. It validates preparation fingerprints, effect intent binding, settled result digests, exact evidence receipts, decision-event identity, revision count, budget snapshot, and control snapshot. The placeholder decision procedure and its old schema were removed without a compatibility reader.
- `accept`, `fail`, and `inconclusive` preserve the exact checked candidate and verification truth. `revise` durably consumes a bounded candidate-revision budget, records the instruction with disposition provenance, and projects it into the next immutable model-turn snapshot. A zero revision limit rejects the first revision without erasing the candidate or checks.
- Resume reuses an already-appended decision without reevaluating it, recovers a settled queryable evaluator effect without replay, keeps unknown outcomes explicit, and suspends on a missing or changed evaluator implementation. Durable verifier and candidate receipt keys bind the exact turn/request attempt, so revisions cannot collide with earlier settlements.

## Evidence

- Tests cover all four decisions, exact input shape/receipts/digests, instruction projection, zero-budget exhaustion, duplicate drive, implementation mismatch, process interruption before the decision event, after the event, and after the decided transition, plus queryable effect recovery with one external start and one decision.
- A negative contract test proves an effect policy cannot bypass the durable effect boundary by returning a decision directly. State decoders reject contradictory policy hashes, preparation fingerprints, effect settlements, output digests, revision/budget snapshots, and unsupported fields.
- Agent Core `npm run verify:release` passed locally with 343 unit tests, 165 focused tests, build, lint, and packed-consumer declaration checks. The final four-platform release gate passed on Ubuntu current, Ubuntu minimum Node 24.8.0, macOS, and Windows: https://github.com/Ismail-elkorchi/agent-core/actions/runs/33170836731.
- Agents compiled, linted, passed 71 tests (67 pass, 4 environment-gated skips), and passed packed-consumer checks against the final pinned Agent Core contract. Coding Agent exposes the deciding phase, both disposition failure reasons, the strict candidate-revision budget field, and a zero revision limit without a compatibility default.
- The release gate exposed a stale self-hosting assertion that ordered parallel `tool.ended` telemetry by source position. The test now proves exact-once tool membership while leaving completion order unconstrained, matching D3's durable immediate-settlement contract; five repeated local smoke runs and the full cross-platform gate passed.
