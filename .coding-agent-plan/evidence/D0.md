# D0 evidence

Status: done

- Started from Agent Core `50749d7eeb9626e936dd3522c7d371ea5f9b36b8` after R0 and E0.
- The implementation must replace process-owned run progression and approval-only reconstruction with one total, generation-fenced operation transition interpreter while preserving the existing finalizer and event ledger as the sole durable authority.
- Confirmed an R0 integration gap: the generic event store exposed only the latest event, not the latest operation transition promised by R0. The in-progress D0 change adds a derived per-event-type pointer index. Every pointer is sequence/hash/offset-bound to the JSONL authority, the index is content-hashed and rebuildable, and memory/JSONL tests prove bounded lookup and reopen behavior.
- Added the in-progress total operation contract and coordinator: complete discriminated states, explicit next-procedure/wait/completion selection, conditional acceptance, generation-fenced attachment, read-only inspection, unfinished listing, abort races, and a lease that conditionally appends semantic facts before transitioning control.
- Refactored the existing finalizer to consume an injected append authority while retaining the event repository for audit/reconciliation. This is necessary for the finalizer to re-enter through the fenced driver; the finalizer itself is not replaced.
- Checkpoint `92e604d7deec1ba3c219040ac0b0c478f4ef93e7` integrates normal runtime progression with the durable driver. Provider, tool, verification, abort, finalization, semantic-event, and terminal-operation writes now share its conditional tail authority; an abort that loses a tail race retries against current truth, and a stale local driver refreshes before cleanup/finalization.
- The existing finalizer is still the only finalization procedure. A successful `run.ended` is followed by one terminal operation transition bound to its exact event identity; failed finalization leaves the operation at a reconcilable finalization phase.
- `AgentSession.restore()` is now read-only and classifies claimed/suspended submissions from operation truth instead of failing claimed work. `resumePending()` explicitly drives recovered work. Session input projection is idempotent by run identity, and operation suspensions distinguish approval, provider uncertainty, tool uncertainty, missing implementation, and user decision.
- Dynamic context input now crosses one exact semantic decoder before it enters retained operation state. Runtime cancellation is durably requested before the local abort signal is delivered.
- Verification at `92e604d7deec1ba3c219040ac0b0c478f4ef93e7`: build/lint passed; 320 unit tests and 147 focused tests passed; packed consumer and exact-optional declaration checks passed.
- Checkpoint `8fbf015dd79156444aa8ad932bbae6a999c75042` closes the driver foundation. Active cancellation is serialized through the owning driver, cancellation is committed before its local signal is delivered, immediate and finalization-boundary aborts are deterministic, and suspended submissions retain their admitted input so abort can drive only cancellation/finalization.
- Coding Agent and Writing Agent migrated at `a4abd2d3ec342e83eae295355d9dcbce49b8fd39`: both supply the exact event-backed operation coordinator, asynchronous abort is awaited, and non-approval suspensions remain distinct from approval UI.
- The original D0 acceptance text contained a dependency cycle: it required deletion of approval-specific reconstruction even though the total per-call continuation that replaces it belongs to D2, while D2 depends on D0. The criterion is deliberately split. D0 permits only that isolated pre-D2 reconstruction; D2 must persist approval and call continuation state and delete `resumeApproval()`, `ResumeExecutionState`, and the audit scan without aliases.

Agents build/lint, all 37 application tests, and the explicit non-approval suspension TUI test pass against the new Core API.
