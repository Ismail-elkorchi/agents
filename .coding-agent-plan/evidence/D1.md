# D1 evidence

Status: done

## Implemented contract

- Every provider exposes a mandatory, versioned `implementationId`; an attempt captures that identity, the exact normalized request digest, the provider recovery capability, and conservative prompt/completion token exposure reservations before invocation.
- Provider execution uses the E0 authority lifecycle: the driver durably records an issued one-shot ticket, claims it before network access, and records one terminal settlement before projecting the assistant response into the conversation.
- `provider.attempt.settled` contains the sanitized final `ModelResponse` and may reference protected provider continuation state. It rejects inline provider state, raw provider payloads, and raw reasoning.
- Recovery reuses a durable settlement without issuing another request. A started attempt without a durable settlement becomes `provider_outcome_unknown`; no provider advertises reconciliation or idempotent replay it cannot prove.
- Live driver takeover cannot duplicate a request: the old driver loses commit authority, while the replacement observes the still-pending external effect and suspends it as an unknown outcome.
- Committed intent that never acquired its start ticket is closed without invoking the provider. It is not guessed into a network request after recovery.
- Provider state restored from a durable settlement remains available to later turns.
- Generic retry policy was removed from the runtime, budgets, events, provider sessions, provider implementations, configuration, and tests. Recovery is now capability-specific instead of treating every provider failure as replayable.
- D1P remains explicitly deferred. Streaming chunks, tool-call fragments, and visible partial output are progress only and cannot prove final settlement.
