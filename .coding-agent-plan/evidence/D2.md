# D2 evidence

Status: done

## Implemented contract

- The authoritative operation state now owns the exact ordered tool calls, current call position, normalized input, implementation identity, effects, approval request and decision, issued or started E0 authority, complete durable observation, and the separate projection phase. Semantic audit entries no longer reconstruct live tool state.
- Sequential calls advance through `ready`, `effect_ready`, `effect_pending`, `settled`, `projecting`, and `complete`. External execution starts only after the one-shot ticket transition is durable. The complete normalized observation and artifact/evidence references settle before conversation projection.
- Each started tool effect conservatively reserves one `tool_invocations` exposure. Known settlement retains that usage; an unknown result retains the reservation rather than refunding it.
- A replacement driver can accept only the exact late settlement authorized by the original settlement permit. The stale driver then synchronizes, observes lost ownership, and cannot project, start another call, or finalize the run.
- Recovery is capability-specific. Unknown effects suspend without replay. A preconditioned operation may reexecute only when the tool proves the same captured resource versions. Buffered/queryable/idempotency-backed implementations may reconcile an exact settled observation through their versioned recovery callback. Recovery callback output crosses one strict runtime boundary.
- Approval is one durable per-call phase. `resolveApproval()` verifies the exact fingerprint, implementation and authorization boundary, records the decision idempotently, and resumes the ordinary driver. `resumeApproval()`, pending-ID reconstruction, `ToolCallRecoveryState`, and the old uncertain-effect terminal result were deleted without aliases.
- Missing or changed tool implementations produce an explicit `missing_implementation` suspension. Preparation resources and resource leases are released across denial, approval, abort, recovery, settlement, ownership loss, and projection failure.
- Session tool-call projection is idempotent by durable call identity and compares canonical call content, so recovery cannot duplicate a conversation tool call or mistake JSON property order for a conflict.
