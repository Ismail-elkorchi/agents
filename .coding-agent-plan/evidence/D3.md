# D3 — Parallel completion and source-order projection

Status: done

## Implemented contract

- The authoritative tool phase now stores one strict current-schema state per source call plus a durable concurrency cap and contiguous projection cursor. Calls independently move through preparation, issued intent, started effect, settlement, projection, unknown outcome, or cancellation; the removed batch-wide `nextCallIndex` schema has no compatibility reader.
- A bounded dynamic scheduler starts only calls whose explicit dependencies are settled and whose resource effects do not conflict with any started or still-possibly-started unknown call. Unrelated calls continue as capacity becomes available instead of waiting for a static wave.
- Each external completion commits its complete observation and settles only its exact effect permit immediately. `tool.ended` follows completion order. Conversation/session observation projection is a separate idempotent transition and advances only through the contiguous source-order settled prefix.
- Driver replacement reconciles every call independently. Unstarted stale tickets are reissued for the new generation; recoverable started effects query their captured capability; unknown effects are never replayed; and a live stale owner can settle its exact outstanding permit without regaining control. An unresolved started call continues to consume concurrency and resource-conflict capacity.
- Approval resolution uses the same post-attach recovery boundary as ordinary resume. Cancellation durably closes every unstarted effect and marks every started uncertain effect before finalization.
- The obsolete exported wave scheduler and its test path were deleted. Runtime execution now owns the only scheduling policy.
