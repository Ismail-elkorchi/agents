# Q1 — Repeated real-model product evaluation

Status: current

- Q1 starts from Agents `b1226f2cadf7065ee6270fe022a2b9a4ce82c78f`, Agent Core `bfefe709fb544c3324b3aa61e328a4c2737fc94c`, Terminal UI `01277f04674c5f021cbe93dccfe378bacec7b632`, and Sandbox `c5c3f63f64fe820a7a43be7b5aaeee1ad252d709` after Q0 completed with strict native and cross-platform evidence.
- The initial campaign will use three independent runs per task. Mixed per-task outcomes trigger expansion to ten runs before a regression conclusion. Development and holdout sets are versioned separately; holdout task bodies are disclosed to the campaign runner only after the evaluated product, prompt, tools, and policy revisions are fixed.
- Every run record must repeat-bind the provider implementation, immutable model digest, prompt and tool-contract input hashes, policy/configuration hash, Sandbox probe/backend evidence, all repository commits, task content hash and split, repetition, exact outcome, provider token usage, local-cost basis, elapsed time, machine-grader identity, and human-audit disposition. Campaign metadata alone cannot stand in for a missing run binding.
- Binary distributions use 95% Wilson score intervals and retain every individual outcome. Quality regression requires like-for-like dimensions; a decline of at least 0.15 with non-overlapping Wilson intervals is actionable, while smaller samples are reported as insufficient evidence. Any machine-observed forbidden mutation is reported individually and remains a Q0 deterministic invariant rather than being adjudicated by a model grader.
- Deterministic graders own file identities, allowed/forbidden paths, terminal facts, and recovery evidence. Human/model disagreement is recorded as `disputed`, never silently averaged; the audit expands to every run of that task version. The initial human sample is stratified across both splits and pass/fail outcomes, with at least 20% of runs and a minimum of eight records. Q1 cannot complete while that sample is merely pending.
- Real-model execution is an explicit campaign command and is never part of blocking CI. CI will validate the current-only record schema, task corpus, deterministic grader, distribution calculations, and report reproduction without contacting a provider.
