# S0 evidence

Status: done

## Implemented contract

- Sandbox now owns a private cross-process execution repository with caller-supplied stable execution IDs, exact request-digest binding, one admission directory, authenticated loopback control, cursor-addressed output, terminal receipts, explicit uncertainty, and bounded terminal/expired identity retention.
- Preparation and activation are distinct. Sandbox publishes the exact prepared summary, enforcement report, policy digest, execution digest, and expiry before Coding Agent invokes its authorization callback. Denial cancels preparation without executing the target; there is no ambient fallback.
- A detached execution host owns the prepared session and target lifecycle. Application-process loss does not revoke it. Replacement callers query the same identity and consume its durable output or final receipt instead of replaying the command.
- Helper loss, operating-system restart, power loss, or record corruption do not claim recovery. They become an explicit unknown outcome, block new Coding Agent command effects, and require an application decision before `acknowledgeUnknown()` removes the retained uncertainty.
- Coding Agent's `SandboxCommandExecution` is the fail-closed adapter to Agent Core's neutral command behavior. It binds the deterministic tool-effect owner to the Sandbox execution and request digests, requires the one adopted physical workspace grant, preserves output cursors and UTF-8, authenticates every query/input/termination request by tool owner, and reconciles terminal or unresolved receipts on attachment.
- Agents records the exact Sandbox source commit and verifies both source checkouts before every build. The dependency targets the sibling Sandbox package directly; no duplicate facade or vendored sandbox was introduced.

## Proven durability tiers

- Application process termination: supported and tested. The detached host, output log, receipt, and query authority survive the admitting caller.
- Sandbox helper termination: detected as unknown; the isolated target tree is terminated; no automatic replay.
- Operating-system restart and power loss: not claimed. Durable files are fsynced, but a previously live external effect is deliberately reported as unknown because execution settlement cannot be proven.
- Storage corruption, truncation, or checksum failure: diagnosed as a corrupt unknown record and never interpreted as successful or replayable.
