# A1 — Configuration and private state ownership

**Intent:** Separate user/product policy, repository proposals, and durable private state.

**Work:** Move runs, sessions, artifacts, locks, journals, trust, and protected transcripts to the platform user-state directory keyed by canonical workspace identity. Discover optional project configuration only through SEC0. Split values into user/organization authority ceiling, project proposals/narrowing, invocation choices, and captured run configuration.

**Acceptance:** No repository-local `.coding-agent` state; private permissions; deterministic precedence with field-level provenance; no hidden Ollama/model fallback; unknown provider/model is an explicit setup state; malformed config fails before runtime; project config cannot widen authority; stale locks and moved/replaced workspace identity are handled explicitly.
