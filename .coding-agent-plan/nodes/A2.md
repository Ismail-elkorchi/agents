# A2 — Repository orientation and scoped instructions

**Intent:** Give the model a useful coding contract without granting repository authority.

**Work:** Add the default coding behavior: inspect before editing, preserve unrelated changes, diagnose before patching, use structured mutations, run meaningful checks, distinguish observation from assumption, and report files/checks/uncertainty. Discover hierarchical `AGENTS.md` and configured instructions with root-to-leaf scope, deterministic precedence, source attribution, content hash, and trust treatment.

Provide a bounded initial repository description: adopted root identity, VCS/non-VCS state, existing dirty changes, package manifests, applicable instruction sources, and proposed verification commands. Do not eagerly inject the full tree. Build sanitized Git inspection that disables external helpers, textconv, credential prompts, hooks, and untrusted configuration unless explicitly needed.

**Acceptance:** Nested scopes, conflicting instructions, hostile text/control characters, symlinked instructions, non-Git roots, worktrees/submodules, dirty/untracked files, and omitted/partial discovery are deterministic. Repository instructions influence behavior only according to SEC0 and never grant capabilities. Context is bounded and attributed.
