# A2 — Repository orientation and scoped instructions

**Intent:** Give the model a useful coding contract without granting repository authority.

**Work:** Add the default coding behavior: inspect before editing, preserve unrelated changes, diagnose before patching, use structured mutations, run meaningful checks, distinguish observation from assumption, and report files/checks/uncertainty. Discover hierarchical `AGENTS.md` and configured instructions with root-to-leaf scope, deterministic precedence, source attribution, content hash, and trust treatment.

Provide a bounded, non-executing initial repository description: adopted root identity, VCS marker or non-VCS state, package manifests, applicable instruction sources, and proposed verification commands. Do not eagerly inject the full tree. Repository orientation must not invoke Git or another repository-defined executable in the host process. Exact Git branch and change inspection belongs to G0 after sandbox composition because even apparently observational Git operations can invoke configured filters, filesystem monitors, text conversion, credential helpers, and other repository-controlled programs.

**Acceptance:** Nested scopes, conflicting instructions, hostile text/control characters, symlinked instructions, non-Git roots, worktree/submodule markers, and omitted/partial discovery are deterministic. Git roots explicitly report that status needs the sandbox-backed inspection capability; no host Git process runs. Repository instructions influence behavior only according to SEC0 and never grant capabilities. Context is bounded and attributed.
