# A3 — Permission modes and sandbox composition

**Intent:** Present one truthful product authority model.

**Work:** Replace scattered `--apply`, `--allow-shell`, project risk lists, and direct process manager use with explicit permission mode, trust state, exact tool set, egress/network policy, and execution target. Coding-agent commands and verification use the sandbox-backed C2 port. Project configuration can only narrow the user/organization ceiling.

The UI/CLI shows what can read, write, execute, access network, and leave the workspace; exact prepared sandbox policy/digests/enforcement accompany approval. If the selected sandbox is unavailable, execution remains unavailable.

**Acceptance:** Matrix-test every trust/permission mode; denied tools are absent rather than constructed with unreachable authority; no ambient command path remains in coding-agent; sandbox enforcement is machine-checked before display; approval fingerprints bind effect, input, root, policy, implementation, and generation; revocation/abort/takeover releases authority.
