# A4 — Verification oracle and result truth

**Intent:** Prevent repository-controlled or agent-modified verification from silently certifying the candidate.

**Work:** Add implementation identity to neutral checks. Coding-agent captures the pre-edit oracle manifest and baseline when feasible, materializes the exact candidate, runs structured sandboxed checks, and records result class/coverage. Check definitions from the repository are proposals until policy admits them.

If a disposition evaluator or check is deterministic, bind its implementation ID and canonical input/output hashes. If it invokes a model, command, network, or other external process, model it through D1/D2 rather than hiding it in a callback.

**Acceptance:** Fixtures cover a weakened test, changed test command, changed package/compiler/CI config, added legitimate test, dependency/lockfile change, pre-existing failure, targeted-only pass, full pass, unavailable check, verifier workspace mutation, underspecified target, underspecified blast radius, and correct clarification instead of guessing. Results bind the exact candidate and cannot use a mutated live workspace as invisible proof.
