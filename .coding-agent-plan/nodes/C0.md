# C0 — Root-bound file capability

**Intent:** Confine every host-side file tool independently from command execution.

**Work:** Replace `workspaceRoot: string` services with one adopted, closable root capability. All workspace discovery/read/image/write/edit/create/replace/delete operations and structured patch journals consume it. Artifact storage uses its own separately adopted root. Generic tools deny `.git` and private application state; coding-agent VCS inspection is separate.

Start with a platform threat/implementation proof. Use held directory/file authority or a package-owned native mechanism where required. Do not ship a portable path-check claim that cannot withstand a live path swap. A platform without the required primitive reports the affected action unavailable.

**Acceptance:**

- Tests cover lexical escape, absolute/UNC/device names, case/normalization aliases, symlink and magic-link chains, hard links, junctions/reparse points, mount crossings where relevant, special files, root replacement, parent and final-component swaps before and during use, and a concurrently hostile process.
- Reads prove that the opened handle is inside the adopted root before bytes can enter evidence/provider context. Discovery never follows an unadmitted alias.
- Mutations bind exact before identity/hash; create/replace/delete publish through the capability; a hard-linked external inode is not modified in place; path changes become explicit conflicts.
- Journals/temporary/backup files have bounded private placement, same-filesystem atomic publication where claimed, sync and cleanup semantics, and process-loss recovery.
- `.git`, coding-agent private state, outside-root secrets, and released capabilities are inaccessible through generic tools.
- Linux, Windows, and macOS each have a tested guarantee matrix. Unsupported hostile-race guarantees fail closed rather than downgrade silently.
