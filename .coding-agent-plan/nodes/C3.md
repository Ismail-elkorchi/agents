# C3 — Deterministic candidate disposition

**Intent:** Permit bounded accept/revise/fail/inconclusive progression without coding semantics.

**Contract:** A disposition policy consumes only the exact persisted candidate, check results/evidence receipts, budget/control snapshot, and captured policy identity. It has a versioned implementation ID. A pure evaluator's canonical input/output digest is recorded before its decision advances control. A missing/different implementation suspends rather than silently rerunning different logic.

Any model, command, clock-dependent, network, or other nondeterministic evaluator is an explicit D1/D2 effect with intent and settlement. It is never executed inside a store mutation. Revision counts and budgets are durable.

**Acceptance:** Accept/revise/fail/inconclusive, crash before/after decision commit, implementation mismatch, exhausted budget, duplicate drive, and evaluator effect recovery all have one result. No repository/test concept enters Core.
