# D0 — Total operation transitions and general driver

**Intent:** Replace process-owned run flow and approval-only recovery with one durable interpreter.

**Public behavior:** Domain-neutral operations equivalent to `accept`, `attach/inspect`, `drive`, `requestAbort`, and unfinished-operation listing. `AgentSession.submit()` remains a convenience over durable acceptance and local driving.

**Work:** Define one discriminated total state for preparation, provider, tool, approval, verification, disposition, finalization, suspended, terminal, cancellation, and unknown-effect states. Every transition is planned purely and committed through R0. `attach` fences the prior driver. Drive executes at most the next admitted procedure and is safe to call repeatedly.

Use the existing finalizer for finalization states. Reconcile session submission and run state by exact IDs/receipts; do not let independent `claimed` flags override a resumable run or let an ended run remain claimed.

**Acceptance:**

- Restore is read-only and never starts effects.
- Each valid state selects exactly one next procedure or one explicit wait/user decision; invalid states are corruption.
- Stale drivers lose planning/start authority but an already-started effect can still submit its exact settlement.
- Abort, takeover, steering/follow-up admission, and finalization races have one conditional-commit winner.
- Recovery cost meets R0 bounds.
- `resumeApproval()` special reconstruction and unconditional claimed-submission failure are deleted after all consumers use the driver.
- Writing-agent compilation/tests demonstrate no coding concepts entered Core.
