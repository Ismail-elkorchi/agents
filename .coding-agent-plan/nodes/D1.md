# D1 — Minimum durable provider attempts

**Intent:** Survive provider uncertainty without duplicate logical responses or invented usage.

**Work:** Before invocation, commit exact request/configuration/provider implementation identities, parameter/context digests, provisioned response identity, E0 recovery capability/expiry, and conservative budget reservation. Persist exactly one final settlement containing validated visible content, final structured tool calls, user-visible provider reasoning summary when supplied, provider continuation state under its protection policy, response/usage identities, usage, and next total operation state.

Do not persist generic raw private reasoning. Partial structured tool-call fragments are inert data and never executable. On restore, query/resume/idempotently retrieve only when the captured provider contract proves it; otherwise close as interrupted/unknown or require user policy. Never interpret a local continuation object as proof the remote request did not happen.

**Acceptance:** Kill before intent, after intent/before network, while network is live, after remote completion/before settlement, during settlement, and after settlement. Prove one logical response, no unsafe duplicate request, correct/unknown usage reservation, expiry behavior, parameter binding, stale-owner behavior, and protected-state redaction. Current providers default to unknown where their APIs cannot prove more.

**Deferred partial-output slice (`D1P`):** Durable visible-output checkpoints are not a V0/P0 dependency. If later justified, persist only user-visible output, inert partial tool-call data, opaque provider continuation state, and provider-supplied visible reasoning summary. Define maximum checkpoint bytes, total retained bytes, minimum interval, latest-wins coalescing, backlog behavior, non-authoritative failure semantics, encryption/redaction/permissions, and deletion or supersession after final settlement. Never checkpoint raw chain-of-thought.
