# E0 — Effect ownership and recovery contracts

**Intent:** Replace the misleading replay/idempotency trichotomy and make stale-owner behavior explicit.

**Work:** Introduce domain-neutral effect intent, start ticket, settlement capability, recovery capability, external execution identity, expiry, parameter digest, and conservative exposure reservation. Capture the capability with the intent; a later implementation declaration cannot retroactively make an old effect safer.

Provider adapters and tools expose only capabilities they actually implement. Default is unknown. Side-effect-free reads need captured resource preconditions. Idempotency needs service binding and retention. Buffered file mutations refer to C0 receipts/journals. Sandbox executions refer to S0 identities/receipts.

**Acceptance:**

- A stale generation cannot issue/start new tickets; a ticket is consumed once.
- A settlement capability can settle only its exact outstanding effect and cannot advance unrelated operation state.
- Takeover never starts a concurrent replacement for a potentially live effect.
- Late settlement, expiry, cancellation, unknown result, mismatched parameters, and unavailable query are explicit state transitions.
- Budget tests retain conservative unknown cost/usage after process loss.
- Remove `pure | idempotent | non_idempotent` where it falsely drives recovery; scheduler conflict semantics continue to use resource accesses/locks, not recovery labels.
