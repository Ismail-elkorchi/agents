# G0 — Sandboxed Git repository observation

**Intent:** Obtain useful repository status without granting repository-controlled Git configuration ambient host execution.

**Dependencies:** A2 establishes bounded non-executing orientation. S0 supplies a fail-closed execution boundary and durable receipt. This node owns Git policy and interpretation in Coding Agent; neither Agent Core nor Sandbox learns repository semantics.

**Work:** Define one exact, non-interactive Git inspection request executed through the selected sandbox policy. Bind executable identity/version, physical workspace root, read-only filesystem grant, denied network, environment, argv, configuration policy, output bounds, timeout, driver generation, and receipt identity. Treat `.git`, config includes, attributes, filters, hooks, fsmonitor, textconv, external diff, credential helpers, submodule helpers, and pager/editor invocation as executable repository surfaces. Either construct a proven inert Git configuration or deny the observation when the installed Git/sandbox cannot enforce it. Parse bounded machine output into branch/head and dirty/untracked entries with explicit partial coverage.

Do not expose Git metadata through the generic root file tools, do not use a host-process Git fallback, and do not call repository-selected commands merely to classify them as status.

**Acceptance:** Non-Git roots, ordinary repositories, linked worktrees, submodule roots, bare repositories, detached HEAD, hostile local/global/system configuration, includes, clean/process filters, fsmonitor, hooks, textconv/diff drivers, pagers/editors, credential helpers, hostile filenames, very large status output, timeout, cancellation, receipt expiry, and sandbox unavailability have deterministic outcomes. Hostile helpers do not execute, status paths remain attributed untrusted data, output truncation is explicit, and every observation binds the exact sandbox enforcement/receipt identity. No ambient fallback exists.
