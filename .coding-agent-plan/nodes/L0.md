# L0 — Ledger structure and validator

**Intent:** Make implementation coordination bounded and conflict-resistant before parallel work.

**Work:** Commit this root ledger, create the split layout described above, generate the root summary from the manifest, and add a validator. The manifest records node ID, dependencies, status, current owner, owned repository paths, source SHAs, decision/evidence paths, and last verified commit. Only the coordinator changes it.

**Acceptance:**

- Validation rejects an unknown status, duplicate ID, missing dependency, cycle/impossible wave, `done` without evidence, stale source SHA, two current owners for one node, one owner assigned overlapping active paths, or conflicting path ownership.
- A node context bundle is generated from only global rules, the node, dependency decisions/evidence, applicable repository instructions, and fresh heads.
- Parallel fixture updates to disjoint evidence files merge without editing the manifest or generated summary.
- The authoritative path/branch and coordinator rule are tested and recorded.
