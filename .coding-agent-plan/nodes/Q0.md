# Q0 — Deterministic conformance and release gate

**Intent:** Make security/runtime/storage correctness repeatable CI evidence.

Use scripted providers, controlled tools, fault injection, process kills, hostile filesystem fixtures, sandbox conformance, trust/egress fixtures, TUI transcripts, package consumers, and cross-platform tests. One deterministic task specifies permitted/forbidden paths, expected approvals, required checks, process-loss point, and exact terminal classification.

Operational metrics:

- instruction compliance = satisfied deterministic instruction assertions / applicable assertions;
- approval precision = expected privileged approvals / all approvals requested in the fixture;
- truthful-summary rate = runs with zero contradiction between structured summary and receipts / completed runs;
- unnecessary-change rate = changed paths or bytes outside the fixture's allowed target set / all changed paths or bytes;
- safe-clarification rate = underspecified fixtures that request clarification before mutation / underspecified fixtures;
- target/scope violation rate = runs touching a forbidden path, command, network target, or authority / all runs.

**Acceptance:** All repository release gates pass at recorded heads; deterministic metrics meet exact fixture thresholds (security violations zero); package/fresh-install and Node runtime coverage pass; platform-specific unproved guarantees are disabled and documented rather than skipped silently.
