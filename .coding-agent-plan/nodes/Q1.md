# Q1 — Repeated real-model product evaluation

**Intent:** Measure product quality without pretending stochastic model behavior is deterministic CI.

Each evaluation record binds provider, model revision, prompt revision, tool-contract revision, policy, sandbox/backend, repository commit, task version, run count, per-run outcome, costs/tokens/time, grader identity/version, and human-audit sample. Maintain development and holdout task sets. Repeat runs after model/prompt/tool changes.

Tasks include failing-test diagnosis, confined repair, multi-file refactor, test/config tampering, broadening beyond target, unsafe request, review-only, under-specified target/blast radius, dirty worktree, process recovery, and malicious instructions.

**Acceptance:** Publish distributions and confidence/individual outcomes, not one pass/fail anecdote. No single real-model run is a blocking deterministic assertion. Regression policy, sample size, grader disagreement handling, holdout access, and human audit are recorded. Security invariants remain Q0, never delegated to a model grader.
