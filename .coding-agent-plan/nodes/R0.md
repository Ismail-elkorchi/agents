# R0 — Conditional durable run store

**Intent:** Supply the storage semantics on which a durable multi-process driver can truthfully depend.

**Contract:** Replace blind append with a run-store operation that conditionally commits against `{tailSequence, tailHash, driverGeneration}` and supports atomic admission/claim/transition batches where the state machine requires them. The successful ledger append is the one control linearization point. Derived index publication may follow but cannot change truth.

Idempotency keys are scoped to the exact run/operation/transition or effect settlement namespace and bind the canonical payload digest. They remain effective for the whole period in which the state machine could retry that action; expiry cannot reopen a duplicate-effect path. Index lookup is not a linear scan.

The store must expose a bounded tail/latest-transition read and a streaming full-audit read. Its index stores only verified offsets and exact record sequence/hash, is published by atomic replace plus directory sync, and is discarded/rebuilt if stale, corrupt, missing, or ahead of the ledger.

**Failure behavior:**

- Reject stale expected tail or driver generation without writing.
- Acknowledgement occurs only after the authoritative record is newline-complete and file-synced according to the documented local-filesystem contract.
- Disk full, quota, permission loss, read-only remount, interrupted write, failed file sync, and failed directory sync produce a typed `not_committed`, `committed_but_index_unknown`, or `outcome_unknown` result; callers never infer success from a thrown generic error.
- Repair only an incomplete uncommitted final record. Complete-record checksum/sequence corruption, truncation before the indexed tail, and conflicting idempotency payloads quarantine the run and forbid effects.
- State roots/files/locks/indexes use private permissions. Lock takeover plus the monotonic store fence prevents a stale live writer from committing even if a stale lock is removed or a PID is reused.

**Bounds:** Warm recovery is proportional to the latest bounded transition plus unfinished calls. Cold index rebuild is `O(total records)` time but bounded memory; ordinary append and idempotency lookup do not retain or scan all history. Explicit full integrity audit may be linear.

**Conformance before D0:** Run the same suite against memory and JSONL stores, plus two live OS processes. Cover conditional races, stale fences, idempotency conflicts, torn tails of arbitrary size, middle corruption, truncation, stale/corrupt index, file and directory sync failures, disk-full/permission fault injection, crash during index replacement, private permissions, memory bounds, and reopen after OS-process death. Record filesystem/platform limits instead of generalizing them.
