# S0 — Sandbox durable-execution conformance

**Intent:** Prove and, only where proven missing, add the sandbox contract required by E0 and C2.

**Tests first:** Exact argv/executable transport, cwd/root grants, environment identity/redaction, network/process/filesystem/resource requirements, prepare expiry/cancel/one-shot consumption, output bounds, cleanup, caller process death, helper death, OS restart where claimed, and two live callers using one execution identity.

The expected gap is a caller-provisioned durable execution ID with query/follow/cancel/final-receipt semantics and bounded result retention after caller loss. Confirm it against current source; if missing, implement it in `sandbox`, not in Agent Core. Define parameter digest binding, who persists receipts, retention/expiry, result cursors, cleanup status, and the response when the execution or receipt has expired.

**Acceptance:** A replacement driver queries before any retry; two callers cannot start the same execution twice; a stale owner cannot acquire a new sandbox execution ticket; late completion produces one queryable receipt; unavailable/expired state becomes explicit unknown; requested guarantees fail closed; no ambient fallback; sandbox's complete conformance and security gates pass at a recorded commit.
