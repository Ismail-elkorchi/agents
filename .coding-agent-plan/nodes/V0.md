# V0 — First resilient CLI slice and stop/go gate

**Intent:** Validate composition before parallel tools, comprehensive TUI work, generic revision loops, or the final model matrix.

**Required path:**

```text
CLI only
one scripted provider and one real provider
one durable accepted operation
one scoped repository instruction
one root-bound read
one structured edit
one sandboxed direct command
one required verification check with oracle manifest
one process termination and recovery
one machine-derived change/check summary
```

Use sequential tools. The termination scenario must include one safe pre-effect recovery and one effect-intent case that is queried, settled, or truthfully remains unknown. It need not wait for parallel settlement, durable partial streaming, exact user undo, full TUI integration, or broad model evaluation.

**Stop/go acceptance:**

- The path is useful on a real small repository and deterministic with the scripted provider.
- No cast, duplicated authority, independent operation state, special-case recovery method, ambient fallback, or coding-agent patch around Core/Sandbox/Terminal UI was required.
- Store recovery is bounded; trust and file containment hold; verification binds the exact candidate; final facts match receipts.
- Record an explicit `go`, `revise R0/D0/E0/C0/SEC0/S0`, or `stop` decision. Wave 9 is blocked until `go`.
