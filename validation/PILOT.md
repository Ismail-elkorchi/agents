## Proposed workload

- Tasks: `persistence-lock-ownership`, `provider-usage-completeness`,
  `resource-coverage-correction`, with exact snapshots and checks generated by
  `prepare-evaluation.mjs`. These are exposed development diagnostics.
- Comparisons: exact A/B and B/C commit pairs in `project-tasks.mjs`.
- Two repetitions per task per pair, alternating order; 24 attempts total,
  concurrency 1. Keep every timeout, infrastructure failure and wrong patch.
- Provider: OpenAI. Model: `gpt-4.1-2025-04-14`. Reasoning: unsupported/provider
  default (no artificial reasoning setting). Temperature 0, max output 4096.
  Same normal tools and `full_host` permissions **inside** the network/PID
  sandbox on every build. No judge.
- Per attempt: 15 minutes application wall time, 80 model turns, 800,000 prompt
  tokens, 80,000 completion tokens and 240 tool calls, partitioned among
  scripted runs. Independent checks: 180 seconds each. Ordinary context only.
- Report actual renewal occurrence; if none occurs, this pilot cannot answer
  renewal-quality questions. Do not replace it with forced-renewal results.

Planning assumption, **not a current vendor quote**: $2/M input and $8/M output
tokens, no cache discount. At 80k input/8k output per attempt, expected provider
cost is about **$5.38 total**. At the declared token allowances the arithmetic
bound is **$53.76**, excluding in-flight overshoot and unknown usage. Refresh
pricing and model availability before approving; neither figure is a spending
enforcement mechanism.

## Required approval and blockers

Proposed absolute spend ceiling: **$60 total**, enforced by a genuinely prepaid
or provider-enforced scoped account/gateway, not a billing notification or an
evaluator flag. Reserve the full remaining possible charge for every admitted
request; reject unknown prices/usage and new work at the boundary. An already
in-flight request can incur charges before settlement.

Before this can run:

1. Approve tasks, exact model, repetitions, settings and the $60 ceiling.
2. Implement and qualify the narrow paid-provider transport and external hard
   spending boundary; current configuration rejects both. Keep credentials
   outside candidate namespaces/manifests. Do not introduce a second accounting
   engine.
3. Qualify A, B and C at their exact revisions, including RPC compatibility,
   release gates and provider configuration. No old-format readers or shims.
4. Requalify interrupted-session continuation on each exact pilot build and
   verify installed dependencies, not only Git pins. Current runtime fixes do
   not repair historical binaries. Retain failures; never retry uncertain effects.
5. Select genuinely long natural tasks and independently curate a blind held-out
   set before making general product-quality claims. The reserved draft task is
   not unseen to the author. Historical Core tasks may reveal clues through the
